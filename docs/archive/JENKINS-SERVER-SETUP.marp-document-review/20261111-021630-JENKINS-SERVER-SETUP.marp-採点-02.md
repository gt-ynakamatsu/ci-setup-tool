### [重要] JDK 21 が無いときの停止条件

- 対象箇所: 「既存ガイドとの違い」。表の直後の「JDK 21 が見つからない場合、スクリプトは「JDK 21 の java.exe が見つかりません。現在の Jenkins LTS は Java 21 または 25 が必要です。」と表示して停止します。」
- 問題: 未導入のサーバーでは、`C:\jdk21` に `java.exe` が無いと、その場で停止するのではなく、Adoptium から ZIP を取得して `C:\jdk21` へ展開してから探し直す。引用の停止は、その後も `java.exe` が無いときだけである。
- 理由: 停止文言自体は `Setup-JenkinsServer.ps1` と一致する。ただし「見つからない場合は停止」だと、この資料の対象である未導入サーバーでは JDK 21 の取得前に止まると読める。直後ではない「スクリプトが行うこと」に展開の手順があるため、資料全体の結論は壊していない。
- 減点: 正確性 -2

### [軽微] 有効でないプラグインの再実行

- 対象箇所: 「導入するプラグイン」。6 個が有効かを確認したうえで、「不足がある場合は、更新サイトへの通信を確認して同じコマンドを再実行します。再実行時は未導入のプラグインが対象になります。」
- 問題: 再実行で導入し直すのは、PluginManager 上で未導入の ID だけである。インストール済みで無効のプラグインは、再実行では有効にならない。
- 理由: 「未導入のプラグインが対象」はスクリプトと一致する。その直前の「有効か確認し、不足なら再実行」は、無効化されたプラグインも再実行で戻るように読める。初回導入で無効のまま残ることは通常は起きにくい。
- 減点: 正確性 -1

### 提案

- 「実行前に決めること」の「導入される版」に、.NET SDK は 8.0 チャネルの、取得時点の版であり、パッチは固定しない、と足す。Git、JDK、Jenkins だけが並んでいる。
