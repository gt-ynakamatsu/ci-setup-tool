### [重要] `C:\jenkins` を削除する前に起動タスクを止めていない

- 対象箇所: 「ログインできないときの扱い」（p.55）と「`C:\jenkins` を削除する前に停止する」（p.56）
- 問題: 停止手順は `java.exe` と `cmd.exe` を `Stop-Process -Force` で止めるだけです。タスク `CISetup Jenkins` と `CISetup Jenkins Agent` を無効にしていません。`C:\jenkins` を消すコマンドも書かれていません。
- 理由: スクリプトの `Invoke-WithStartupTasksSuspended` には「無効化しないと、強制終了を失敗とみなして 1 分後にタスクが二重起動する」とあります。タスクは異常終了時に1分間隔で10回まで起動し直す設定です（`-RestartCount 10 -RestartInterval 1分`）。サーバー再起動後にタスクから Jenkins が動いている状態でこの手順を行うと、削除中か削除直後に Jenkins が SYSTEM で起動し直すおそれがあります。その場合、ファイルが使用中で消せないか、`C:\jenkins` の一部が作り直されます。「対象が表示されなくなったことを確認」しても、その1分後の再起動は防げません。
- 修正案: 停止の前に `Disable-ScheduledTask -TaskName 'CISetup Jenkins','CISetup Jenkins Agent'` を入れます。停止を確かめたあとに `Remove-Item 'C:\jenkins' -Recurse -Force` を実行し、最初と同じコマンドで再実行する、という順にします。
- 確認事項: 再実行で `Register-ScheduledTask -Force` が登録し直したとき、タスクが有効に戻るか。戻らない場合は、`Enable-ScheduledTask` を手順に加える必要があります。

### [重要] 後半の完了確認では、プラグインが有効かどうかを確かめていない

- 対象箇所: 「9. プラグイン7個を確認する」（p.71）、「16. 完了を確認する」（p.78）の1番
- 問題: 後半の完了条件は、実行ログの `OK: all plugins already installed (...)` に7個の ID があることです。しかし jenkins_client.py の `_install_plugins_script` は `pm.getPlugin(id)` が null でないかしか見ません。読み込みに失敗したプラグインや無効のプラグインも「installed」に数えます。前半のスクリプトは `isActive()` で有効かどうかまで確かめ、`OK: plugins active` を完了条件にしています。前半と後半で、同じ「7個そろった」の意味が違います。
- 理由: 依存関係の不足などでプラグインが無効のままでも、後半では「完了」と判断できてしまいます。その場合、後で作る CI ジョブが失敗します。ほかにも細かな点が2つあります。
  - p.71 のコードブロックは実際の出力（1行）を折り返して書いており、出力そのものではありません。
  - 出力の順序は `REQUIRED_PLUGINS` の順で毎回同じなので、「順序や改行ではなく」の断りは要りません。
- 修正案: 9番に「`Manage Jenkins → Plugins` の Installed plugins で7個が有効になっており、エラー表示がないことを確認する」を加えます。16番の1番も「7個の ID があり、Plugins 画面で有効」とします。コードブロックは実際の1行のまま載せます。
