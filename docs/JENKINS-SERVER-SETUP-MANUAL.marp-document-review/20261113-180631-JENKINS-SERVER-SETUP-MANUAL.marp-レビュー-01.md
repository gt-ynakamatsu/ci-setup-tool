### [重要] エージェント PC の Java 要件を「11 以上」に下げた結果、接続できない Java を選ぶ余地が生じた

- 対象箇所: 「13. エージェント PC を準備する」の手順1「Java 11 以上をインストールする」と手順2「`java -version` で Java を実行できることを確認する」
- 問題: 原文は「Java 21 または 25」に限定し、版も確認させていた。改稿案は「11 以上」に下げ、手順2も「実行できること」だけの確認にしたため、版の確認がなくなった。
- 理由: 「11 以上」の根拠は CISetup の起動コマンドのコメント（`Java 11+ 必要`）と、環境スキャンの案内（`JRE 11+`）である。ただし手動手順で入れるのは現行の Jenkins LTS で、参照スクリプトは「現在の Jenkins LTS は Java 21 または 25 が必要」としている。エージェントの `agent.jar` がサーバー本体の Java 要件に追従していれば、Java 11 や 17 を入れた PC は「windows-agent のオンライン確認」という目的に届かない。原文の「サーバーとそろえて 21 または 25」のほうが、どちらの場合でも動く。改稿で選択肢を広げたことで、失敗の可能性が生まれている。
- 修正案: 原文どおり「Java 21 または 25 をインストールし、`java -version` のメジャー版が 21 または 25 であることを確認する」に戻す。CISetup が「Java 11+ 必要」と表示する点は、原文の注記を残して「表示は 11+ だが、この手順ではサーバーとそろえる」と説明する。
- 確認事項: 対象の Jenkins LTS で `agent.jar` が動く最低の Java 版。11 で動くと確認できた場合だけ「11 以上」にする。動かないと確認できた場合は、記述が事実と食い違うので重大になる。

### [重要] 同一サーバーでエージェントを動かすときの受信規則が、何をすればよいか分からない

- 対象箇所: 「11. エージェント用 TCP ポートを設定する」の手順6「接続元を、エージェントを動かす PC に限定する」と末尾の段落「同一サーバーでエージェントを動かす場合は、CISetup に入力した URL と通信経路に合わせて受信規則を設定します」
- 問題: 原文には「受信規則が必要」「接続元はそのサーバーの IP アドレスにする」という具体的な指示があった。改稿案ではこれが「URL と通信経路に合わせて」に置き換わり、規則を作るのか作らないのか、接続元に何を入れるのかが書かれていない。手順6の「エージェントを動かす PC」も、同一サーバーの場合に何を指すかが不明である。
- 理由: CISetup が出す起動コマンドは、CISetup に入力した Jenkins URL（`-url "{base_url}/"`）へ接続する。読み手はこの URL を把握しているが、「通信経路」を自分で判断する材料はない。参照スクリプトのコメント（ループバック通信は受信規則の対象外）からすると、原文の「受信規則が必要」は誤りだった可能性がある。それでも改稿案の表現では作業者が操作を決められず、TCP ポートが原因でオンラインにならないときの切り分けもできない。
- 修正案: 同一サーバーの場合の扱いを一つに決めて書く。例:「同一サーバーでエージェントを動かす場合、通信はサーバー内で完結するため受信規則は不要です。別 PC のエージェントがあれば、その PC の IP アドレスを接続元にします。」手順6は「別 PC のエージェントがある場合は、接続元をその PC に限定する」と条件を付ける。
- 確認事項: Jenkins URL にサーバー自身のホスト名や IP アドレスを入れたとき、同一サーバーのエージェントの TCP 接続が受信規則なしで通るかを実機で確認する。
