### [重要] localhost を避ける条件が「別 PC の CISetup」だけになっている

- 対象箇所: 「3. CISetup から接続を確認する」の末尾「別 PC の CISetup から接続する場合、Jenkins URL には `localhost` ではなく…」
- 問題: エージェント PC がサーバーと別の場合の条件がありません。この場合、CISetup をサーバー上で動かしていても `localhost` は使えません。
- 理由: `setup_server` は、⑤ に入力した URL を Jenkins URL として設定します。同じ URL がエージェント起動コマンドの `agent.jar` 取得先と `-url` にも入ります（`jenkins_client.py` の `_build_agent_launch_command`、`_set_location_script`）。サーバー上の CISetup で `localhost` を入れると、別 PC のエージェントは接続できません。
- 修正案: 「CISetup またはエージェントをサーバー以外の PC で使う場合は、`localhost` ではなく、設定用 PC とエージェント PC の両方から到達できるホスト名か IP アドレスを入力します。この URL はエージェント起動コマンドにも使われます。」とする。

### [重要] 組み込みノードの実行数が 0 にならないことに触れていない

- 対象箇所: 「4. Jenkins サーバーを初期設定する」の最後の段落、「8. オンラインと接続成功を確認する」
- 問題: スクリプト経路では組み込みノードの実行数を 0 にします（前半「エージェントを確認する」、スクリプトの `setNumExecutors(0)`）。CISetup の初回設定はこれを行いません（`setup_server` は接続確認、プラグイン、URL、ノード登録、コマンド取得だけです）。後半にはこの違いが書かれていません。
- 理由: エージェントラベルが空欄の場合、Jenkinsfile は `agent any` になります（`help_texts.py` の `AGENT_LABEL`）。MSI 版の組み込みノードに実行数が残っていると、ビルドが `windows-agent` ではなく Jenkins サーバー本体で実行され得ます。.NET SDK や Git のないサーバーで失敗するおそれがあります。
- 修正案: 手順8に「`Manage Jenkins → Nodes` → Built-In Node → Configure で実行数を 0 にする」を加える。または「エージェントラベルを `windows-agent` と同じ値にそろえる」方法を書く。
- 確認事項: MSI 版 Jenkins の組み込みノードの既定の実行数。
