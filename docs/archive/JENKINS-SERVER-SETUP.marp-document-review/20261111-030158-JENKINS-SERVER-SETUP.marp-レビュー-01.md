### [重大] 停止時の対処表が再実行へ戻らず、API Token が無いまま終わる

- 対象箇所: 「主なエラーと対処」の `Jenkins が 8 分以内に ...` 行と `エージェント ... が 3 分以内にオンラインになりませんでした` 行。「再実行の前に」の「再実行の前に、起動済みの Jenkins とエージェントのウィンドウを閉じてください。」
- 問題: エージェント行の対処は「エージェントウィンドウを閉じ、`start-agent.bat` を実行」で終わっている。スクリプトはエージェント待ちでタイムアウトすると `throw` で終了し、その後の API Token 発行（`Write-Step "API トークンを用意"` 以降）と完了表示を実行しない。この行のとおりにエージェントをオンラインにしても、`C:\jenkins\cisetup-api-token.txt` は作られず、CISetup へ入力する API Token が手に入らない。Jenkins の 8 分行も同じで、`start-jenkins.bat` を手で起動した後にどうするかが書かれていない。プラグイン導入、エージェント登録、API Token 発行は、いずれも未実行のまま残る。さらに「再実行の前に」はウィンドウを閉じるよう指示しており、「起動して様子を見る」対処と方向が逆になっている。
- 理由: 表のとおりに操作すると、目的である接続テストへ進めない。スクリプトは起動中の Jenkins（`jenkins.war` を含む java.exe）とエージェント（`agent.jar` を含む java.exe）を検出して再利用するため、ウィンドウを開いたまま再実行しても動く。閉じる指示は必須ではなく、手で起動する対処との関係を一本化できる。
- 修正案: 表の各行の対処を「原因を確認したあと、同じコマンドで再実行する」に揃える。ウィンドウの扱いは、「閉じてから再実行する」と「起動したまま再実行する（スクリプトが既存プロセスを使う）」のどちらかに決めて、「再実行の前に」と表で同じことを書く。エージェント行と Jenkins 行は「ウィンドウの表示で原因を確認し、解消したら再実行する。完了表示が出るまで API Token は発行されない」とする。

### [重大] 管理者パスワードに使えない文字の制限が消え、`$` を含むと初期化に失敗する

- 対象箇所: 「用意するもの」の「認証処理が ASCII を前提としているため、管理者パスワードには ASCII 文字を使用します。先頭と末尾には空白を入れません。PowerShell のコマンドでは、値を単一引用符で囲みます。」
- 問題: スクリプトは、パスワードの `\` と `"` だけをエスケープし、Groovy の二重引用符文字列 `realm.createAccount("$groovyUser", "$groovyPassword")` へ埋め込む。Groovy の二重引用符文字列では `$` が変数展開になる。そのため `$` を含むパスワードでは、初期設定用 Groovy が失敗するか、別の値で管理者アカウントが作られる。その結果、`Jenkins へのログインに失敗しました。` で止まる。エラー文の案内どおり `C:\jenkins` を削除して同じパスワードで再実行しても、同じ失敗が繰り返される。原文には「`$` は初期設定用 Groovy の文字列展開になるため入れません」「`'` も入れません」とあったが、改稿で削除された。今の記述は「ASCII であればよい」と読めるため、`$` を含むパスワードを許してしまう。
- 理由: 記載された条件を守っても手順が失敗し、再実行でも回復しない。`$` は管理者パスワードによく使われる記号である。
- 修正案: 原文の制限を戻す。「ASCII のみ。`$`、`'`、`"` は使わない。先頭と末尾に空白を入れない」と書き、理由を一文添える。理由は、認証ヘッダーは前後の空白を除くが、アカウント作成時の値はそのまま保存されるためである。
- 確認事項: `"` は Groovy 用のエスケープはされるが、`powershell -File` へネイティブ引数として渡る時点で崩れる可能性がある。禁止文字に含めるかどうかは、実機で確かめてから決める。

- 問題: スクリプトは `Start-Process` で Jenkins とエージェントのウィンドウを開くため、デスクトップのないリモート PowerShell では使えない。原文にあった「WinRM などのリモート PowerShell では実行しない」は削除された。また、ポートは `-Port` で変えられるのに、8080 に固定した書き方になっている。
- 理由: 前提が暗黙になっている。
- 修正案: WinRM の一文を戻す。「TCP 8080（`-Port` の値）」と書く。

### [提案] 対象の OS と PowerShell の版を書く

- 対象箇所: 「対象」「実行条件」
- 問題: 対象の Windows Server の版と PowerShell の版が書かれていない。スクリプトは `Invoke-WebRequest` で github.com などから HTTPS で取得するが、TLS のプロトコルを指定していない。
- 理由: 古い OS の Windows PowerShell 5.1 では、TLS 1.2 が既定で無効になっていて、ダウンロードに失敗することがある（参照資料外の一般的な事象で、未確認）。
- 修正案: 動作を確認した OS の版を書く。古い版を対象に含める場合は、TLS 1.2 を有効にしておくことを前提に加える。
- 確認事項: 対象とする Windows Server の版で、スクリプトの取得処理が通るか。

### [提案] Jenkins 更新サイトの通信先を具体的に書く

- 対象箇所: 「初回実行時の外部通信」の「Jenkins プラグイン: Jenkins 更新サイト」

- 確認事項: 実際の通信先（一般には updates.jenkins.io と、そのミラーへのリダイレクト。参照資料外のため未確認）。

### [提案] 接続テスト失敗時の CISetup の表示と対処を対応させる

- 対象箇所: 「接続テストが失敗したとき」
- 問題: CISetup の失敗時の表示は、`jenkins_client.py` で決まっている。認証の問題なら「Jenkins 認証エラー (401 Unauthorized)」、到達できなければ「Jenkins サーバーに接続できませんでした。」になる。手順書はこの区別をせず、確認項目を順に並べている。
- 理由: 表示を見て、確認する箇所を絞れるようになる。
- 修正案: 「接続できませんでした」なら手順1〜3（到達性）、「401」なら手順4〜5とトークンの再発行（重要「API Token を発行し直す方法が無い」の修正案）を行う、という対応を書く。設定用 PC にプロキシが設定されている場合の確認も加える（CISetup は Python の urllib を使うため、OS のプロキシ設定が効く可能性がある。未確認）。
