### [重大] 正確性: 同一サーバーのエージェント接続をループバックと書いている

- 対象箇所: 「11. エージェント用 TCP ポートを設定する」の手順5と、その直下の「同一サーバーの接続はループバックであり、受信規則の対象外です。」
- 問題: 後半の起動コマンドは、CISetup に入力した Jenkins URL へ接続する。手順は、別 PC から届く URL を使い、その URL に `localhost` を使わないと指示している。同一サーバーをエージェントにする場合も接続先はその URL であり、`127.0.0.1` へのループバックではない。受信規則を追加しない、という手順は、エージェント用 TCP 50000 への接続を止める判断になる。
- 理由: `cisetup/jenkins_client.py` の起動コマンドは `-url` に Jenkins URL を入れ、`agent.jar` もその URL から取得する。前半の `tools/Setup-JenkinsServer.ps1` は `http://localhost:<Port>/` へ接続し、TCP 50000 の規則を `127.0.0.1` に限定する。後半の文は、このスクリプトの動作を MSI 版の同一サーバー構成へ当てている。Windows の受信規則の対象外になるのはループバックアドレスだけで、サーバー名や LAN の IP 宛ては対象になる。正確性から6点減点した。
- 減点: 正確性 -6

### [重大] 論理性: 使わせる URL と、受信規則を不要とする説明が同時に成立しない

- 対象箇所: 「3. Jenkins の初期設定を行う」の「別 PC から接続する URL には `localhost` を使いません。」と、「11. エージェント用 TCP ポートを設定する」の手順5、6
- 問題: 設定用 PC から開く URL を `localhost` 以外にしたうえで、同一サーバーのエージェントもその URL で起動する流れになっている。その直後で、同一サーバーなら受信規則は不要だとしている。別 PC をエージェントにする場合だけ規則を追加する、という分岐も、同一サーバー側の接続先がループバックであることを前提にしている。
- 理由: 前半の完了条件と同じく、後半も `windows-agent` のオンラインを完了条件にしている。同一サーバーで MSI 版を使う担当者は、この分岐に従って TCP 50000 を開けない。接続先の URL と受信規則の要否が対応しておらず、完了確認まで進めない判断になる。論理性から4点減点した。
- 減点: 論理性 -4

### [重要] 実用性: `C:\jenkins` を削除する前に起動タスクを止めていない

- 対象箇所: 「ログインできないときの扱い」と「`C:\jenkins` を削除する前に停止する」
- 問題: プロセスを `Stop-Process -Force` で止めたあと、対象が見えなくなったら `C:\jenkins` を削除する、という手順になっている。`CISetup Jenkins` と `CISetup Jenkins Agent` を無効にする操作がない。
- 理由: スクリプトは両タスクをサーバー起動時の SYSTEM 実行として登録し、異常終了時は1分間隔で10回まで起動し直す。再起動後の再実行でタスクがプロセスを動かしているときに強制終了すると、タスクは失敗とみなして起動し直す。スクリプト自身は、プロセスを止める前にタスクを無効にしている。無効にしないと、削除中にプロセスが戻り、削除後の再実行が起動中の Jenkins を再利用する。初回実行でスクリプトが直接起動したプロセスだけを止める場合は、起動時のタスクはすぐには動き出さない。再起動後にこの回復手順を使う場合に、削除が完了しない。実用性から2点減点した。
- 減点: 実用性 -2
