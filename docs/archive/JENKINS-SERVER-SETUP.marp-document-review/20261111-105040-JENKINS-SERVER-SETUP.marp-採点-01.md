## 減点

### 【重要】実行条件に、サーバー自身から Jenkins URL への到達を置いている

- 項目: 正確性 -3、論理性 -1
- 対象箇所: 「実行条件」の「Jenkins サーバー自身から、指定する Jenkins URL へ到達できる」
- 問題: この到達を、初回実行の条件として置いている。
- 理由: `Setup-JenkinsServer.ps1` の起動待ち、API、`agent.jar` の取得、エージェントの `-url` は `http://localhost:<Port>/` だけを使う。`-JenkinsUrl` は Jenkins のルート URL として保存し、完了表示へ出す値である。サーバーがその URL へ接続する処理はない。同じ資料の後段は、エージェントが `http://localhost:<Port>/` を指定し、設定用 PC が Jenkins URL を開く、と書いており、この条件とつながらない。接続テストに必要なのは、隣の箇条書きにある設定用 PC からの到達である。
- 重大にしない理由: コマンド、削除対象、成功判定を誤らせる記述ではない。到達できない環境で手順を始めない判断にはなり得るため、重要とする。

### 【軽微】取得物の確認と削除を、全ダウンロード共通のように書いている

- 項目: 正確性 -1
- 対象箇所: 「取得物を削除して再実行する場合」の「ダウンロード中にエラーになったファイルと、ファイルの種類を確認できなかったファイルは、スクリプトが削除します。確認するのはファイル先頭の2バイトです（ZIP は `PK`、EXE は `MZ`）。」
- 問題: 確認方法と、失敗時に消える範囲が、実際の分岐より広い。
- 理由: `Download-File` は通信例外と種別不一致でファイルを消す。先頭2バイトの確認は zip（`PK`）と exe（`MZ`）だけである。`C:\dotnet-install.ps1` は text で、空でないことだけを見る。`agent.jar` は `Download-File` を通らない。署名不一致では消すが、`Invoke-WebRequest` が例外になったときは残る。Git の exe、JDK と Jenkins の zip については記述と一致するため、重大にはしない。電子署名やハッシュを見ない、という文はスクリプトと一致する。

### 【軽微】パスワード前後の空白を除く理由が、認証ヘッダーに閉じない

- 項目: 明瞭性 -1
- 対象箇所: 「用意するもの」の「パスワードは ASCII 文字だけで作り、先頭と末尾に空白を入れません。スクリプトは認証ヘッダーを ASCII で作り、前後の空白を取り除くためです。」
- 問題: 空白を除く対象が、文面ではパスワード全体に読める。
- 理由: ASCII で認証ヘッダーを作る記述は、`Get-BasicHeaders` と一致する。前後の空白を取り除くのは、そのヘッダーに使う値だけである。初期設定用 Groovy へ渡すパスワードと、パスワードファイルへ書く値は `Trim` しない。前後に空白があると、作成されるアカウントと認証ヘッダーがずれ、ログイン失敗になり得る。空白を入れない、という指示自体は妥当である。`$`、`"`、`\` を Groovy へ渡すときに退避する、という続きは `Escape-Groovy` と一致する。

### 【軽微】作業フォルダの大文字が、完了表示の既定文字列と違う

- 項目: 整合性 -1
- 対象箇所: 「作成される主なファイル」の `C:\jenkins\workspace\agent.jar` と `C:\jenkins\workspace\start-agent.bat`
- 問題: 資料は `C:\jenkins\workspace`、完了表示の既定値は `C:\Jenkins\workspace` である。
- 理由: `JenkinsHome` の既定値は `C:\jenkins`、`AgentWorkDir` の既定値は `C:\Jenkins\workspace` である。検証ログの完了表示も `作業フォルダ: C:\Jenkins\workspace` である。Windows では同じ場所を指す。完了表示とパスを突き合わせるとき、大文字が違う。

### レイアウトは、実描画を見ていないため満点にしない

- 項目: レイアウト -2
- 対象箇所: スライド全体。密度が高いのは「検証状況」、「主なエラーと対処（導入）」、「主なエラーと対処（JDK・Jenkins）」
- 問題: 文字切れ、余白、重なり、コントラストは未確認である。宣言された文字サイズに対して、上記3枚の行数が多い。
- 理由: `section.small` は本文 24px、表 20px、コード 18px、余白は 48px 64px、画面比は 16:9 である。「検証状況」は確認5項目と未確認4項目で、長い行が折り返す。「主なエラーと対処」の2表は7行から8行で、セル内の文も長い。見出し、表、箇条書き、コード、節区切りの構造は揃っているため、未確認だけを理由に大きくは削らない。

## 提案

減点しない。

- 「スクリプトの処理」の4番は、JDK と .NET SDK の両方を入れた後に PATH を足す並びである。スクリプトは .NET SDK の PATH 追加のあとで JDK を展開し、その `bin` を PATH の先頭へ足す。
- 「待ち時間」の「プラグイン導入は、失敗すると最大3回まで自動でやり直します」は、試行が3回であることと、3回失敗で止まることのどちらにも読める。ループは3回で、失敗のあいだは30秒置く。エラー文言は「プラグインの導入に 3 回失敗しました」である。
- 「主なエラーと対処（JDK・Jenkins）」の応答待ち失敗は、「必要なら手動起動し、そのまま同じコマンドを再実行」とある。`start-jenkins.bat` を実行した PowerShell は Jenkins が終了するまで戻らない。同じ資料の「Jenkins の起動を確認する」には、別の管理者 PowerShell で再実行するとある。
