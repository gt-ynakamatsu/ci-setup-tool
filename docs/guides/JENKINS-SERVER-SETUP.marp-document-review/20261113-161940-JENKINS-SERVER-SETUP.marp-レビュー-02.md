### [重要] 「Jenkins を再起動する」手順が Windows の再起動になっていて、操作が大きすぎる

- 対象箇所: 67 ページ「7. Jenkins を再起動する」の手順1～3
- 問題: 見出しは Jenkins の再起動ですが、手順はサーバー OS 全体の再起動です。プラグイン導入後に必要なのは Jenkins の再起動だけです（`ops.py` の表示は「プラグインインストール後、Jenkins の再起動が必要です。」）。
- 理由: 共有サーバーでは、OS の再起動はほかの利用者やサービスを止めます。MSI 版は Windows サービスとして動きます。`environment_scan.py` も、サービス名 `Jenkins` を `sc query Jenkins` で確認しています。
- 修正案: 「Jenkins サーバーの管理者 PowerShell で `Restart-Service Jenkins` を実行する」→「設定用 PC で Jenkins URL を開き、ホーム画面が開くまで待つ」→「CISetup で『Jenkins サーバーを初期設定』をもう一度押す」に置き換える。OS の再起動は代わりの方法として1文で添える程度にする。
- 確認事項: MSI 版 Jenkins のサービス名が `Jenkins` か。社内でサービスの再起動に承認が必要か。

### [重要] サーバー側の Java の準備がなく、エージェント側の Java の版も CISetup の表示と食い違う

- 対象箇所: 61 ページ手順4、72 ページ手順1と手順5
- 問題: MSI より前にサーバーへ Java を入れる手順がありません。72 ページは Java 21 または 25 を指定していますが、起動コマンドの先頭行は「Java 11+ 必要」です。環境スキャンの Java の確認は版を確かめないため、手順5では 21 または 25 であることを確認できません。
- 理由: MSI の画面で Java を求められても、担当者は何を入れればよいか分かりません。資料と CISetup の表示で版が違います。
- 修正案: 61 ページの前に「Jenkins サーバーに Java 21 または 25 を入れる」を加える。72 ページに「起動コマンドのコメントにある『Java 11+』ではなく、21 または 25 を入れる」と書き、`java -version` で版を確認する手順を加える。
- 確認事項: 対象の Jenkins LTS と MSI が求める Java の版。起動コマンドのコメントを開発側で直すか。

### [重要] エージェント用 TCP ポートの受信許可が、同一サーバーの場合も接続元を限定しない

- 対象箇所: 70 ページ手順4と手順5
- 問題: 同一サーバーをエージェントにする場合でも、接続元を限定しない受信規則ができます。前半のスクリプトは `127.0.0.1` に限定しています（`Setup-JenkinsServer.ps1` の 989～992 行）。固定するポート番号の決め方もありません。
- 理由: エージェント用ポートが社内ネットワーク全体へ開き、前半とセキュリティの水準がそろいません。
- 修正案: 同一サーバーでは受信規則を追加しないか、接続元を `127.0.0.1` に限定する。別 PC では接続元をその PC に限定する。手順2に「ほかの用途で使っていなければ前半と同じ `50000` に固定する」と書く。

### [重要] MSI と初期設定の手順が「出た場合は」と「画面の案内に従う」ばかりで、決める値の基準がない

- 理由: 担当者は何を選べばよいか判断できません。同じ構文の条件文が続く点は作成痕跡にも当たります。
