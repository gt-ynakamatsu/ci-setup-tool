### [重大] 正確性: 後半の Jenkins サーバーを Java 17 以上で進める

- 対象箇所: 「1. Jenkins サーバーへ Java を入れる」（63枚目）。JDK 17 以上を入れ、`java -version` のメジャー版が 17 以上なら先へ進む、とある。続く「2. MSI を入手して値を決める」では、版を固定せず Jenkins LTS の Windows MSI を入手する
- 問題: Java 17、18、19、20 でも確認を通過する
- 理由: `Setup-JenkinsServer.ps1` は Jenkins LTS 2.580.2 を `get.jenkins.io` から取得し、既存の Java は 21 または 25 だけを使う。JDK 展開に失敗したときの文言は「現在の Jenkins LTS は Java 21 または 25 が必要です。」である。同じ改稿案の前半も、このスクリプトの Jenkins を LTS 2.580.2、Java を 21 または 25 としている。後半が入手させる Jenkins LTS に 17 以上を適用すると、Java 17 のまま先へ進み、サーバーが起動しない判断になる。`environment_scan.py` の案内文は「Jenkins サーバー（JDK 17+）」だが、スキャンは `java` があれば検出とし、版では落とさない。案内文に下限を合わせた結果、スクリプトが現在の LTS に課している条件より緩い。正確性から 8 点減点した。エージェント PC の「JRE または JDK 11 以上」と、起動コマンドの `Java 11+` は `jenkins_client.py` と環境スキャンの案内に合うため、この減点には含めていない
