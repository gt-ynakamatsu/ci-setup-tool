### [重要] プラグイン確認で、再起動不要の「INSTALLED:」が失敗と同じ扱いになっている

- 対象箇所: 後半「8. Jenkins サービスを再起動する」の「再起動が必要と表示されなかった場合も、次ページのプラグイン確認へ進みます」。「9. プラグイン7個を確認する」の手順1と、「`INSTALLED:` だけの場合や ID がそろわない場合は、更新サイトへの通信を確認し…再実行します」。「16. 完了を確認する」の項目1
- 問題: `jenkins_client.py` は、足りないプラグインを導入したときに `INSTALLED: <ID>` を返します。` | RESTART required` が付くのは、再起動が必要な場合だけです。再起動不要で導入が済んだときは、再起動の案内が出ず、実行ログは `INSTALLED: ...` になります。それなのに9では `OK: all plugins already installed` だけを正としているため、正常に導入できた担当者にも通信確認をさせてしまいます。逆に、更新サイトに見つからない ID は何も表示せずに飛ばされます。そのため、ID が欠けたことに気づく手がかりは「ID がそろわない」ことだけです。
- 理由: 担当者は、正常な状態を異常と判断して余計な調査をするか、異常な状態を見逃すおそれがあります。
- 修正案: 次のように分けます。
  - `OK: all plugins already installed (...)` に7個の ID がある場合は確認済み
  - `INSTALLED:` の場合は、「Jenkins サーバーを初期設定」をもう一度押し、`OK: all plugins already installed` に7個そろうことを確認する
  - 2回目でも ID がそろわない場合は、更新サイトへの通信を確認する

  16の項目1も「`OK: all plugins already installed` の行に7個の ID がある」と具体的に書きます。

- 修正案: 「同一サーバーで動かす場合も、Jenkins URL のホスト名へ接続します。別 PC のエージェントを後から追加する場合に備えて、規則を作ります」のように、理由を断定しない書き方にします。
- 確認事項: 同一サーバーから自分の非ループバック IP の TCP 50000 へ接続するとき、受信規則が適用されるかを確認してください。
