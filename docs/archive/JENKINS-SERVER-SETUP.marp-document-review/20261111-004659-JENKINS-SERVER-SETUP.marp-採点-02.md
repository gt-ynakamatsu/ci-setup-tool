### [重要] 正確性: 未指定パスワードの実効値

- 対象箇所: 「本番実行の前に決めること」の「未指定時の既定値は `cisetup-admin`」。「パラメーター」の `-AdminPassword`。「スクリプトが行うこと（起動後）」の「起動時の Groovy で管理者、Jenkins URL、TCP 50000 を設定」
- 問題: パラメーター初期値は `cisetup-admin` である。`-AdminPassword` を付けず、`<JenkinsHome>\cisetup-admin-password.txt` があるときは、スクリプトはそのファイルの内容を使う。初期設定用 Groovy は、セキュリティ領域がまだ `HudsonPrivateSecurityRealm` でないときだけ管理者を作り、既存の管理者パスワードは書き換えない。
- 理由: 「未指定時の既定値」は、再実行の実効値と一致しない。パスワードを変えて再実行すれば Jenkins の管理者が更新される、と読める。正確性から 3 点減点した。

### [提案] `-SkipAgent` でも待受ポート 50000 は設定される

- 対象箇所: 「エージェントを別 PC にする場合」
- 問題: この構成で作らないのは TCP 50000 の受信規則である。初期設定用 Groovy は `-SkipAgent` でも待受ポートを 50000 にする。
- 理由: 実行条件のポート競合確認と矛盾はしない。別 PC の節に一行あると、受信規則を作らないことと待受設定を分けて読める。減点しない。

### [提案] プラグイン再起動では Groovy が適用される

- 対象箇所: 「スクリプトが行うこと（起動後）」の「既に Jenkins が動いている場合、新しく書いた Groovy はその場では適用されません。」
- 問題: その文は、起動済みのプロセスには当たらないという意味で実装と合う。プラグイン結果が `RESTART required` のときは、スクリプトが Jenkins を止めて起動し直すため、書き換えた Groovy はそこで実行される。
- 理由: 起動済みのままプラグイン再起動が不要だったときだけ、管理者・URL・待受ポートは更新されない。減点しない。
