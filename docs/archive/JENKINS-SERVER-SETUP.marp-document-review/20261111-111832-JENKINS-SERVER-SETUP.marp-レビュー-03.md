### [重要1] Windows ファイアウォールの「アクセスを許可する」ダイアログに触れていない

- 該当箇所: 「ファイアウォール規則」（317〜319行）「規則の追加に失敗しても処理は続き…」、「接続テストが失敗したとき」（556行）「設定用 PC だけ開けなければ、HTTP の受信規則、ポート、名前解決を確認する」
- 問題: Jenkins の `java.exe` が初めて待ち受けを始めると、対話デスクトップに「Windows セキュリティの重要な警告」が出ることがあります。ここで「キャンセル」を押すと、`java.exe` を対象にしたブロック規則が作られます。ブロック規則は、スクリプトが作るポートの許可規則より優先されます。その場合、`CISetup Jenkins HTTP` は有効なのに、設定用 PC からつながりません。556行の確認項目では原因にたどり着けません。
- 根拠: スクリプトはポート単位の規則だけを作り、プログラム単位の規則は作りません（168行 `New-NetFirewallRule ... -LocalPort $LocalPort`）。Jenkins は `start-jenkins.bat` から対話デスクトップ上で起動されます（177行、370行）。
- 直し方: 「プラグイン反映時の再起動」か「ファイアウォール規則」に、「Java のアクセス許可を求める画面が出たら『アクセスを許可する』を選ぶ。キャンセルしない」と加えます。556行に「`Get-NetFirewallApplicationFilter` などで `java.exe` のブロック規則がないか確認し、あれば削除する」を加えます。
- 確認事項: ポートの許可規則がある状態でこの警告が出るかは、Windows の版と設定で変わる可能性があります。検証環境で一度確かめてから書いてください。

### [重要2] 対象の Windows の版が書かれておらず、古い版では HTTPS の取得が失敗するおそれがある

- 該当箇所: 「対象」（34〜46行）、「主なエラーと対処（導入）」（491行）「ダウンロード中の例外 | 外部通信を確認して再実行」

- 確認事項: 対象の版で既定の `SecurityProtocol` がどうなるかは、参照資料の外の知識です。導入予定のサーバーで `[Net.ServicePointManager]::SecurityProtocol` を確かめてください。

### [重要3] 「必要なプラグインが再起動しても有効になりませんでした」の対処が「直して」で終わっている

## 提案

### [提案1] 設定用 PC のプロキシ設定で接続テストが失敗する場合を加える

- 該当箇所: 「接続テストが失敗したとき」（550〜559行）
- 内容: CISetup は Python の `urllib` で接続します（`jenkins_client.py` 192〜194行）。Windows では、システムのプロキシ設定を使います。設定用 PC にプロキシが設定されていて、例外にサーバー名がない場合、ブラウザーと同じく、つながらないことがあります。手順4に「プロキシの例外に Jenkins サーバー名を入れる」を加えると、社内ネットワークで迷いにくくなります。

### [提案2] 取得する版が固定されていないことを書く

- 該当箇所: 「導入される版と方式」（155〜162行）、「検証状況」（177行）
- 内容: JDK 21 と Jenkins LTS は、実行時点の最新を取得します（304行、327行）。検証時の版（Jenkins 2.580.2、Temurin 21.0.13+9）と違う版が入ることがあります。将来の Jenkins LTS が Java 21 に対応しなくなると、スクリプトは Jenkins の応答待ちで止まります（319行のメッセージも Java 21 または 25 を前提にしています）。「実行時点の最新が入る。検証時の版と異なる場合がある」と添えると、検証状況の読み方がはっきりします。

### [提案3] ポートの使用状況と、サーバー側の応答を確かめるコマンドを載せる

- 該当箇所: 「実行条件」（124行）、「接続テストが失敗したとき」（553行）
- 内容: 124行は「使われていない」ことを条件にしていますが、確かめ方がありません。`Get-NetTCPConnection -State Listen -LocalPort 8080,50000 -ErrorAction SilentlyContinue` で、何も表示されないことを確かめる、と書けます。553行も、ブラウザーのないサーバーを考えると、`Invoke-WebRequest http://localhost:8080/login -UseBasicParsing` の結果で判断できると便利です。

### [提案4] 参照情報のスライドを本文の流れから外す

- 該当箇所: 2章の「作成される主なファイル」「秘密情報の扱い」「管理者設定の注意」（338〜384行）
- 内容: 2章は「実行コマンド → 処理 → 待ち時間 → 完了表示」と進みます。その後、3章の接続テストの前に、参照情報が3枚続きます。初めての人が最後まで通すことを優先するなら、この3枚を末尾の「付録」へ移します。2章の完了表示の直後から3章へ進めるようにします。
